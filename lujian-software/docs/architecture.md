# 路鉴智巡软件架构

## 总体结构

```text
车载采集终端
  │  图像 / 时间 / 坐标 / 速度 / 终端编号
  ▼
数据接入与质量门控
  │  模糊、逆光、遮挡、雨雪筛查
  ▼
YOLOv8 开源模型服务
  │  D00 / D10 / D20 / D40 检测框与置信度
  ▼
聚合与道路匹配
  │  15m 距离合并 / 道路编号 / 桩号 / 多终端频次
  ▼
业务 API（Express）
  ├── 工人作业客户端
  │     地图点位 / 现场复核 / 导航 / 处置回传
  └── 数字孪生管理后台
        病害台账 / 派发研判 / 工单闭环 / 采集终端 / 模型管理
  ├── 合作方服务
  │     车企云端识别接口 / 科研脱敏数据 / 路政订阅
  └── 数据治理
        最小必要采集 / 脱敏 / 权限分级 / 授权边界
```

## 应用层

### 工人作业客户端

- 以 OpenStreetMap 和 Leaflet 展示道路病害点位。
- 展示病害类型、道路编号、桩号、经纬度、终端捕获频次和模型置信度。
- 支持查看研判建议、接单、开始处置、完成处置和跳转 OSM 导航。
- 完成处置前必须上传修复照片；浏览器端先压缩，再随工单归档。
- 移动端将任务列表、地图和详情按纵向组织。

### 数字孪生管理后台

- 道路网络地图与病害空间分布。
- Three.js 路段数字孪生示意图，将病害点、风险和终端频次映射到道路空间。
- 病害台账、状态筛选、风险筛选和检索。
- 依据病害等级、终端频次和置信度形成派发建议，由值班人员决定派发、观察或复核。
- 工单调度与完整证据链。
- 采集终端页面展示后装终端、采集来源、在线状态和试点准备。
- 合作服务页面展示路政、车企、科研与采集伙伴的服务方式。
- 数据处理状态、终端在线状态、模型注册表与许可证提示。
- 数据授权与合规规则，包括最小必要采集、脱敏、权限分级和地图成果边界。

## 服务层

`server/index.mjs` 提供 REST API，并以 `server/data/store.json` 持久化演示数据。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 加载客户端与后台所需数据 |
| GET | `/api/defects` | 查询病害 |
| POST | `/api/defects/:id/review` | 复核、观察或排除 |
| POST | `/api/defects/:id/dispatch` | 创建工单 |
| POST | `/api/orders/:id/status` | 更新处置状态并归档修复照片/说明 |
| POST | `/api/detections/ingest` | 接收推理结果并执行聚合 |
| POST | `/api/pipeline/run` | 运行演示批次 |
| POST | `/api/v1/detections` | 合作方写入检测结果，需 `x-api-key` |
| GET | `/api/v1/road-defects` | 合作方读取脱敏病害字段，需 `x-api-key` |

合作接口演示密钥为 `demo-partner-key`。正式部署应替换为按合作方签发、可撤销和可审计的密钥。

## 生产化缺口

当前交付是本地可运行的演示系统。生产部署还需接入统一身份认证、角色权限、对象存储、消息队列、PostgreSQL/PostGIS、审计日志、HTTPS、地图瓦片代理和真实模型权重。演示环境把压缩后的修复照片写入本地 JSON，生产环境应改为对象存储保存文件、数据库保存引用，并配置访问权限与到期删除策略。
